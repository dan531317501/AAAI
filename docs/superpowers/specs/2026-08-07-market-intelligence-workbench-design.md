# 多市场资金与热点事件市场情报工作台设计方案

**日期**：2026-08-07  
**状态**：待用户审阅

## 一、目标与边界

构建一个本地单用户 Web 工作台，覆盖 A 股、港股和美股，用于每日市场扫描、盘中资金观察、热点新闻阅读和历史回放。

首版目标：

- 交易时段按 1、3 或 5 分钟刷新行情、成交量和可用资金指标。
- 同时保存实时快照、收盘结果和历史数据，支持无网络离线回放。
- 保留各市场原始资金指标，并生成跨市场可比较的标准化资金流评分。
- 提供资金折线图、成交量/成交额柱状图、Top 10 资金流入词云和行业关系网络图。
- 聚合行业/主题、公司、宏观经济、政治与地缘事件新闻。
- 提供五套可切换的视觉皮肤，不改变数据口径和交互语义。

首版不包含自动下单、Level-2/逐笔盘口、多用户权限、云端部署、复杂策略回测和未经授权的新闻全文存档。产品定位是信息整理与研究辅助工具，不直接生成自动投资建议。

## 二、方案选择

采用本地优先的 Web 工作台，而不是快速原型框架或原生桌面应用。

本地运行一个后端服务和一套前端资源，浏览器访问本机地址。后端负责采集、存储、指标计算和 API；前端负责图表、网络图、新闻联动和皮肤切换。首版不拆分微服务，也不引入登录系统。

现有仓库中的 Longbridge 客户端、股票分析和新闻处理资产可以作为数据适配与研究逻辑的基础，但新工作台必须通过统一数据契约消费数据，不能直接依赖分析 Skill 的报告目录结构。

## 三、系统架构与数据流

```text
本地 Web UI
    ↓ HTTP API
本地应用服务
    ├── Scheduler：实时、收盘、新闻和历史任务
    ├── Normalizer：代码、时区、币种和分类统一
    ├── Metrics Engine：评分、排名、异常和关系计算
    ├── News Processor：去重、分类、实体关联和摘要
    └── Data Quality：来源、覆盖率、过期和失败状态
    ↓
市场/新闻适配器 → 原始数据 → DuckDB 本地存储
```

适配器按能力声明是否支持实时行情、历史行情、资金指标、行业数据和新闻。A/H/美股不强行使用同一供应商字段；某市场缺少原生资金指标时，只能标记为 `flow_proxy` 或不可用，不能把价格/成交量估算伪装成真实资金金额。

## 四、数据契约与资金评分

### 主要实体

- `instrument`：市场、交易所、代码、名称、币种、交易时区。
- `price_volume_bar`：价格、成交量、成交额、周期、交易状态。
- `flow_observation`：原始指标名、原始值、资金方向、标准化评分、来源和覆盖范围。
- `taxonomy_membership`：股票、行业、主题、指数之间的归属及来源分类。
- `news_event`：标题、摘要、来源、发布时间、事件时间、影响对象和评分。
- `relation_edge`：节点类型、关系类型、强度、计算窗口和有效时间。

所有记录都保存 `source`、`retrieved_at`、`as_of`、市场本地时间、质量状态和原始字段引用。原始层不可覆盖，统一层负责字段规范化，派生层负责评分和排名；派生值必须可以重新计算。

### 标准化资金流评分

保留供应商原始指标，同时生成 `standardized_flow_score`，范围为 `-100` 到 `100`。默认计算规则为：

- 日线取最近 60 个有效交易日作为窗口。
- 日内取最近 20 个同市场、同交易时段位置的有效交易日作为窗口。
- 将当前值转换为窗口内百分位 `p`，再计算 `round(200 * (p - 0.5))`，最后限制在 `-100` 到 `100`。
- 有效样本不足时评分为不可用；窗口长度和最低样本数可以在配置中调整，但必须随结果保存。

- `0` 表示接近该市场自身历史中位水平。
- 正数表示相对流入增强，负数表示相对流出增强。
- 日线使用滚动历史窗口；日内使用同市场、同交易时段位置的历史窗口。
- 评分不足以计算时返回不可用，不使用未来数据或跨市场字段填补。

评分表示相对强弱，不表示可直接比较的真实资金金额。界面始终同时展示原始值、标准化分数、指标名称、来源和数据更新时间。

## 五、采集、离线回放与恢复

任务按市场交易日历和本地时区调度：

- 交易时段：按配置的 1、3 或 5 分钟间隔采集。
- 开盘前：整理隔夜新闻和市场扫描。
- 收盘后：补齐最终行情、资金排名、新闻聚类和日度摘要。
- 历史任务：回补缺口、重算派生指标和验证数据。

前端使用普通 HTTP 定时查询获取最新状态，不在首版引入 WebSocket。每条快照以来源、代码、周期和时间戳构成幂等键。任务状态统一为 `pending`、`running`、`success`、`partial`、`failed`。

应用重启后检查最近交易时段并执行增量补采；网络超时和限流采用退避重试；不可恢复错误记录原因并在数据状态页展示。离线模式关闭外部请求，使用明确的历史 `as_of` 时间读取本地数据，缺失项显示为缺失，不用未来数据补齐。

## 六、界面与可视化

### 主导航

1. 今日扫描
2. 资金走势
3. 行业关系图
4. 消息中心
5. 历史回放
6. 数据状态

今日扫描页展示 A/H/美股概览卡、资金折线图、成交量/成交额柱状图、Top 10 词云、重大新闻时间线和关系图缩略视图。市场、时间、行业/主题、原始值/标准化值和币种是全局筛选条件；点击行业或主题后，所有图表、新闻和网络图同步联动。

### 四类图表

- 折线图：展示原始资金或标准化资金随时间变化，支持多市场、行业和主题比较，并在时间轴上标记新闻事件。
- 柱状图：成交量与成交额分开展示，支持绝对值和相对历史均值切换。
- 词云图：按选定周期展示资金流入 Top 10，字体大小对应流入强度，旁边同时保留精确排名、数值和覆盖率。
- 网络图：默认限制节点数量，支持按节点类型、时间、关系强度和图深度筛选，避免形成不可读的全量毛线团。

### 网络图模型

节点包括市场/指数、行业、主题、股票、宏观事件、政治事件和新闻事件。边包括成分关系、产业链关系、资金同步关系、价格相关关系和新闻关联关系。

提供三个视图：

1. 资金传播：市场 → 行业/主题 → 股票。
2. 产业链：上游行业 → 中游行业 → 下游公司。
3. 事件影响：宏观/政治事件 → 新闻 → 行业 → 股票。

不同视图采用固定的节点大小语义：资金传播视图使用绝对标准化资金分数，产业链视图使用最近成交额，事件影响视图使用事件影响力与受影响节点数量的组合值。节点颜色表示涨跌或资金方向；边宽表示关系强度；结构性关系使用实线，统计相关或新闻关联使用虚线。点击节点展开一层邻居，点击边查看关系类型、计算窗口和依据。时间滑块支持观察关系变化及事件前后对比。

### 五套视觉皮肤

五套皮肤共享页面结构、组件、数据口径和交互：

1. 量化终端黑：深色背景、紧凑网格、荧光数据色。
2. 金融蓝白：蓝白配色、稳重清晰，作为默认皮肤。
3. 报刊研究风：米白纸张感、衬线标题，适合复盘阅读。
4. 赛博霓虹风：深色背景、紫蓝渐变，突出网络图和热点。
5. 极简灰阶风：低饱和度、留白多，突出数据本身。

皮肤只改变背景、卡片、边框、字体、图表配色和装饰效果，不改变正负方向、数据单位和关系语义。由于 A 股与美股常见涨跌颜色习惯不同，系统还必须显示箭头、正负号和文字方向，不能只依赖颜色。

## 七、消息中心与事件关联

消息分为行业/主题热点、公司与产业链事件、美国经济、政治与地缘事件、市场结构事件五类。来源优先级为官方机构/交易所/监管披露、授权金融新闻源、权威媒体和其他聚合来源；较低等级来源不能覆盖高等级来源的事实字段。处理流程为：抓取 → 标准化 → 重复聚类 → 市场/行业/股票实体关联 → 事件分类 → 相关性、影响力和可信度评分 → 中文摘要 → 关联图表和网络图。

每条消息保留原文标题、中文标题、来源、链接、发布时间、事件发生时间、影响对象、评分和证据层级。相关性和影响力使用 `0-100` 分，可信度使用高/中/低三级；相关性表示与市场对象的直接匹配程度，影响力表示事件范围和市场敏感度，可信度表示来源和多源确认情况。三者不合并为单一情绪分。新闻发布时间与事件发生时间分开保存。

消息中心提供今日要闻、板块热点、宏观与政治、事件时间线四个视图。点击新闻时展示关联行业/股票、事件前后资金和价格变化，以及网络图中的影响链路。系统只显示关联证据，不把统计相关或共同提及直接表述为确定因果。

首版默认保存标题、摘要、来源和原文链接；全文是否保存取决于数据授权。新闻摘要和评分必须能回到来源，不把转载内容伪装成系统原创。

## 八、质量、安全与验收

数据源失败时显示缺失或过期，不生成伪造评分；每个页面显示数据截止时间、来源和覆盖率。凭据只从环境变量或操作系统安全存储读取，不写入行情、新闻、事件和普通日志；本地服务默认只监听本机。

验收覆盖以下场景：

- A/H/美股时区、币种和交易日历正确隔离。
- 原始值、统一值和派生值可追溯且可重算。
- 重复采集幂等，重启后能补齐最近缺口。
- 离线回放不会读取截止时间之后的数据。
- 四类图表、新闻和网络图支持统一筛选与联动。
- 词云有精确排名，网络图可展开并显示关系依据。
- 五套皮肤切换不改变数据和交互语义。
- 新闻去重、来源链接、发布时间和事件时间可验证。
- 网络失败、限流、空数据和部分数据源失败均有可见状态。

测试分为数据规范化/评分单测、供应商适配契约测试、带 fixture 的端到端采集测试、重启和失败恢复测试、离线回放测试以及前端筛选/联动/皮肤切换测试。需要真实凭据的外部行情和新闻 smoke test 单独运行，不作为无凭据的默认测试前提。

## 九、实施顺序

1. 审计现有数据客户端和供应商能力，冻结统一数据契约。
2. 实现 A/H/美股行情、成交量、交易日历和历史回放。
3. 接入原始资金指标并实现标准化评分。
4. 实现今日扫描页和基础图表。
5. 实现新闻中心、去重和事件关联。
6. 实现行业/主题/股票网络图初版。
7. 实现五套视觉皮肤和交互打磨。
8. 完成数据质量、恢复机制和全链路验证。

第 1 步必须先输出供应商能力矩阵，再决定每个市场的具体适配器；不以接口名称相似作为数据语义相同的依据。
